# 规格格式

规格是动手前交给 AI 的输入模板。它不属于程序本身，`src/` 里没有它的代码；到这一步为止它只是一份写法。

## 治什么

偏离有三个断点，规格一一对应。

词汇断点：你嘴里的「提醒」是到点弹一次窗，AI 理解成企业级通知系统。规格用 vocabulary 把词钉死，再列 NOT 显式禁止它自己发挥。

规模断点：不说复杂度上限，AI 默认往完备方向建模。规格用 scope 给出文件数、概念数的上限。

边界断点：不说「不要什么」，AI 就把能想到的都要了。NOT 与 must_not 把不要的东西写明白。

## 两种规格

代码模块写成契约：意图、边界、不变量，分别回答要什么、多大、什么永远成立。测试模块写成断言：场景、期望、不要测什么。两者共用同一套问法，只是落到不同对象上。

不用伪代码、散文或 UML 做载体，它们要么不能机械检查，要么藏得住含糊。

## 和反思的关系

规格是反思的产物，也是反思的输入。某次偏离固化成的规则，最后会变成规格模板里的一行；下次写规格时自动带上，AI 拿到的就是带边界的版本。

举例：规则「需求里的抽象词必须先钉死边界」来自一次真实的过度建模，它落在规格里的位置就是 vocabulary 的 NOT 列表。

## 边界

规格只规定怎么把需求写给 AI，不规定程序内部怎么实现。

## 验收

拿一个真实需求按这份格式写出来，AI 照它实现，产出不越过 scope 的上限。这一步还没做，属于真实环境验收的一部分，见 `eval.md`。
