# reflect 开发指南

这套文档写给接手 reflect 程序的实习生。读完它应当能明白 reflect 为什么存在、每一步为什么长这样，以及动代码时要守住什么。

AI 写错代码好办，语法错、边界错，一跑就知道。麻烦的是另一种：AI 建了一个模型，跟你脑子里想的不是一回事。它能跑，看着也像样，但你要的不是它；你看得出「不对」，说不出哪里不对，也说不清它是怎么走到那一步的。偏离发生在你下需求和它动手之间，过程不可见，事后复盘不了。reflect 把这个过程记下来，让偏离点可查，并把修正固化成下一次动手前的约束。

程序分两半：Skill 管怎么想，命令行管记住什么。`src/cli/` 是命令行这一半。

阅读顺序是 `design.md` 再 `maintenance.md`。前者讲三个动作、三种节点、五条命令各自为什么是现在的样子，以及哪些方案被砍掉了；后者讲怎么改、什么不能改、怎么判断一次改动有没有把闭环弄断。

设计的原始草稿在 `docs/dev-guide/`：`reflect.md` 是设计正本，`reflect_spec.md` 是规格格式，`reflect_test.md` 是开发场景的验证用例。本套文档是对它们的展开；两处说法不一致时以草稿为准，并回来改这里。
