# 反思规范

反思规范管的是怎么想。它不写代码，但规定三个动作每一步问什么、写到什么程度算完。

## 拆解

从一个结论出发，写下它依赖的一到三条前提。结论写当时真正相信的那句；前提写没被写出来、可一旦不成立结论就不成立的那些。写到三条为止。写到四五六条，通常说明结论本身还没想清楚。

## 检验

拿反例去打每一条前提。找得到就标为可疑，找不到就保留。这是三个动作里唯一的真检验：没有反例的反思只是在确认自己本来就信的东西，什么也没改变。宁可这一步粗糙，也不能跳过。

## 固化

把可疑前提连同它的反例，改写成一条可执行的规则，按存储约定的记法落字。规则要能被召回，所以句子里要带事件里会出现的词。

## 边界

规范只管思考质量。判断命中哪条规则是召回的事，文件怎么读写是存储的事。

## 落地顺序

先只做拆解，最容易见效；检验可以先人工，跑通再自动化；最后做固化与检索，闭环才算合上。

## 验收

拿一次真实偏离走完三个动作，产出一条下次能被召回的规则。
