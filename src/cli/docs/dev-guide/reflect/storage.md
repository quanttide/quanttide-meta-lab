# 存储

存储只管一件事：决定反思记下来的东西长什么样，并把它写进文件。

## 记什么

三种节点。结论是当时以为对的东西，比如「AI 这次的实现符合我的意图」。前提是结论压着、却没写出来的东西，比如「AI 理解的『提醒』和我理解的是同一件事」。规则是修正后的前提，写成可执行的句子，比如「抽象词必须先钉边界」。

两条边。结论指向前提，表示依赖；规则指向前提，表示修正。四件东西就够表达反思，别的不需要。

别处常见的反思要素都能落回这几种。必要条件与充分条件只是检验前提的一种问法；框架识别就是更底层的前提；弱点标记是反复出现的坏前提，也就是规则的反面；触发器属于查询逻辑，归命令行，不属于数据。节点少是为了让流程真的跑得动：每多一种，录入时就多一次判断，判断一多，人就懒得记，记不下来后面全废。

## 怎么存

一个 JSON 文件。图数据库能做的，一个文件加几行读写也做得完，而文件可以被 diff、被手工改、被一眼看穿。等召回真的不够用了再换，那时手上有真实数据，换得有依据。

## 边界

存储不判断哪条规则该被召回，那是召回的事；不决定什么时候写，那是命令行的事。它只认记法。

## 验收

写进一批节点读回来一致；手工改过文件后仍能读。
