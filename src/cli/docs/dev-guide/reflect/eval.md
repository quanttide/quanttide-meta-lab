# 验收

前面五件都是零件，验收是看它们合起来有没有用。

## 在哪验收

真实工程环境，拿「工作云」平台上的真实需求。测试样例要重新设计、写一遍再跑。`reflect_test.md` 里的「任务提醒」是编出来的，用来讲清楚原理够了，用来验证不够。

## 判据

三条，缺一不可。存得进：这次偏离拆得成 AI 的推理链，能按存储的记法写下去。召得回：下次 AI 又要过度建模时，check 命中相关规则。拦得住：命中之后，你在它动手前加上了约束。

## 留什么

跑完留下一份记录：这次偏离属于哪一类断点（词汇、规模、边界），固化成了哪条规则，下次什么事件会触发它。这份记录既是验收结论，也是下一轮规格模板的素材。

## 什么时候算过关

三条全过才算可用。只过前两条，说明规则记了却没用上，问题在召回或规则写法；只过第一条，说明反思还在自说自话。
