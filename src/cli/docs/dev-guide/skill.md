# 反思规范

反思规范管的是怎么想。它不写代码，规定三个动作每一步问什么、写到什么程度算完，并规定哪一步落进程序。

## 拆解

从一个结论出发，写下它依赖的一到三条前提。结论写当时真正相信的那句；前提写没被写出来、可一旦不成立结论就不成立的那些。写到三条为止。写到四五六条，通常说明结论本身还没想清楚。

这一步落在纸上，或者直接写进规格，不进程序：程序不做推理，只接产物。

## 检验

拿反例去打每一条前提。找得到就标为可疑，找不到就保留。这是三个动作里唯一的真检验：没有反例的反思只是在确认自己本来就信的东西，什么也没改变。宁可这一步粗糙，也不能跳过。

反例写具体的那件事，不写「可能不成立」这类判断。同样落在纸上。

## 固化

把可疑前提连同它的反例，改写成一条可执行的规则。规则要能被召回，所以句子里要带事件里会出现的词。

落字：`reflect commit <规则> --revises <前提>`。规则修正的那条前提一并记下，召回时会连同规则文本一起算作它的词。

## 边界

规范只管思考质量。判断命中哪条规则是召回的事，文件怎么读写是存储的事。

## 验收

拿一次真实偏离走完三个动作，产出一条下次能被召回的规则。`examples/ai_model_drift.rs` 是这套流程的最小演出，Day 1 固化两条，Day 30 命中。
