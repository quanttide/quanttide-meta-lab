# 五条命令

五条命令对应反思的四个动作——记结论、记前提、找反例、写成提醒，再加一次事后检索。每条下面写清它要什么、做什么、回什么。

`--store <文件>` 是全局参数，放在命令前后都可以，用来换存档文件，默认是当前目录的 `reflect.json`。

## add

```text
reflect add <结论>
```

记下一句你当时相信的判断。同一句重复记，不会多出一条。

```bash
reflect add "AI实现符合我的意图"
```

回你 `已记下结论：AI实现符合我的意图`。

## dep

```text
reflect dep <结论> <前提>
```

记下「这个结论依赖这个前提」。结论或前提哪个还没记过，它会顺手补上；同一对重复记，不会多出一条边。

```bash
reflect dep "AI实现符合我的意图" "AI理解的提醒=我的提醒"
```

回你 `已记下依赖：AI实现符合我的意图 ——依赖——► AI理解的提醒=我的提醒`。

## test

```text
reflect test <前提> [--counterexample <反例>]
```

检验一条前提：标成可疑，并把反例存下来。不给 `--counterexample` 也能跑，只标可疑、不留反例。

```bash
reflect test "AI理解的提醒=我的提醒" --counterexample "AI加了 RetryPolicy、Channel、Template，我根本没提"
```

回你两行，一行说前提被标了，一行把反例复述给你核对。

## commit

```text
reflect commit <规则> [--revises <前提>]...
```

把一条提醒固化下来。不给 `--revises`，它挂到当前全部可疑前提上；给一个或多个，就只挂到指定的那些。

```bash
reflect commit "需求里的抽象词必须先钉死边界"
```

回你一行规则，再把这条规则挂到的前提逐个列出来。

## check

```text
reflect check [事件]
```

动手前跑它。给一句事件描述，按吻合程度列出相关提醒；不给事件，就列出攒下的全部规则。

```bash
reflect check "让AI写用户积分功能，抽象词和边界要说清"
```

```text
命中（25%）：需求里的抽象词必须先钉死边界
  词：ai、抽象、象词、边界
```

比例是「事件里的词有多大一部分对上了」，只用来排序，低到 10% 也可能是正主，关键看规则那句话对不对。「词」那一行是把中文按相邻两字切出来的碎片，用来算吻合度的，不用读。

## 常见问题

### 东西存在哪

默认存在你敲命令的目录下，文件名 `reflect.json`。它是普通文本，能打开看、能改、能备份。换位置用 `--store`。

### 敲错了怎么办

直接改 `reflect.json`，或者删掉重来。工具不藏状态，那个文件就是全部。

### check 说没有命中规则

两种可能：还没固化过规则；或者提醒那句话里没有下次事件会出现的词。规则不是格言，是给未来的自己看的提醒，句子里要带上你会遇到的词。

### 中文要不要加引号

要。带空格或标点的文本用引号包起来最省事，一直加也不会错。
