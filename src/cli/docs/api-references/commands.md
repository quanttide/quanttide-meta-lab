# 两条命令

反思的五个动作里，只有两处需要程序：把固化出来的规则收下来，在动手前把它送出去。每条命令下面写清它要什么、做什么、回什么。

`--store <文件>` 是全局参数，放在命令前后都可以，用来换存档文件，默认是当前目录的 `reflect.json`。

## commit

```text
reflect commit <规则> [--revises <前提>]...
```

把一条提醒固化下来。规则写成可执行的句子，句子里要带上你下次会遇到的那类词，否则 check 找不着它。`--revises` 记下这条规则修正的前提，可以给多次；不给也能跑。

```bash
reflect commit "需求里的抽象词必须先钉死边界" --revises "AI理解的提醒=我的提醒"
```

回你一行规则，再把它挂上的前提逐个列出来。同一条规则再固化一次不会变成两条，新前提并进去、重复的不写第二遍。

## check

```text
reflect check [事件]
```

动手前跑它。给一句事件描述，按吻合程度列出相关提醒；不给事件，就列出攒下的全部规则。

```bash
reflect check "让AI写用户积分功能，抽象词和边界要说清"
```

```text
命中（25%）：需求里的抽象词必须先钉死边界
  词：ai、抽象、象词、边界
```

比例是「事件里的词有多大一部分对上了」，只用来排序，低到 10% 也可能是正主，关键看规则那句话对不对。「词」那一行是把中文按相邻两字切出来的碎片，用来算吻合度的，不用读。

`check` 只读，不写文件：查一次不该凭空生出一个存档。

## 常见问题

### 东西存在哪

默认存在你敲命令的目录下，文件名 `reflect.json`。它是普通文本，能打开看、能改、能备份。换位置用 `--store`。

### 敲错了怎么办

直接改 `reflect.json`，或者删掉重来。工具不藏状态，那个文件就是全部。

### check 说没有命中规则

两种可能：还没固化过规则；或者提醒那句话里没有下次事件会出现的词。规则不是格言，是给未来的自己看的提醒，句子里要带上你会遇到的词。

### 拆解和检验为什么没有命令

它们是思考，不是记录。结论怎么拆成前提、前提被哪个反例打中，写在纸上或写进规格就够了；程序只管收规则、发规则。少一次判断，人少懒一次。

### 中文要不要加引号

要。带空格或标点的文本用引号包起来最省事，一直加也不会错。
