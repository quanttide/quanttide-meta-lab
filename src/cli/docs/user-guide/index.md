# reflect 使用指南

这份指南给第一次用这个工具的人。读完它你能独立走完一次：把一次偏离改写成一句提醒记下来，下次动手前把它叫回来。

## 它解决什么

你有一个判断，后来发现它不对。麻烦的地方在于，你当时并没有把判断背后藏着的东西说出来。

举个真的。你让 AI 写一个「任务提醒」功能，只说了一句话。它建出 Task、Schedule、Notification、Channel、Template、RetryPolicy 一整套，几十个文件。你一看就知道不对，可是说不出哪里不对，也说不出它是怎么走到那一步的。

事后才看清，你当时偷偷依赖了两个前提：你以为「提醒」在 AI 那里也是到点弹一次窗；你以为它会按需求的大小来定复杂度。两个都没写出来，两个都错了。

reflect 只管这条线索的最后一头：把改写出来的提醒记下来，下次遇上同类的事先提醒你一句。前面的拆解与检验是你自己的事，写在纸上就行。

一句话：反思就是把结论拆成前提，检验前提，把修正后的前提固化成规则。

## 先跑起来

工具在 `src/cli/` 下，是个 Rust 项目。先 cd 到 `src/cli/`，也就是这份指南所在目录往上三层。

```bash
cd src/cli
cargo build --release
```

之后就用 `./target/release/reflect`。想省掉这串路径，可以 `cargo install --path .`，之后直接敲 `reflect`。下面为了好读，一律写成 `reflect`，你按自己的情况替换。

## 最短的一次

假设你刚发现「被收编对 IP 不利」这个判断站不住，当年押着它的前提是「收编=失去独立性」，而反例是「分析师转顾问，信息更准、公信力没掉」。把这些压成一句提醒记下来：

```bash
reflect commit "收编是否有利，取决于是否要求闭嘴" --revises "收编=失去独立性"
```

下次遇上同类的事，动手前问一句：

```bash
reflect check "要不要进入体系、被收编、谈合作"
```

```text
命中（10%）：收编是否有利，取决于是否要求闭嘴
  词：收编
```

比例低没关系，意思是「事件里只有一部分词对上了」。它只用来排序，不用来判断，关键看规则那句话对不对。

## 东西存在哪

默认存在你敲命令的那个目录，文件名 `reflect.json`。就是一个普通文本文件，可以打开看、可以改、可以备份、可以拷到别的机器。想换位置，用 `--store`：

```bash
reflect --store ~/我的反思.json check "要不要跟人合作"
```
